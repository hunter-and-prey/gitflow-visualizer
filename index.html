探索開源工作流精髓

選擇適合您專案的分支管理策略，提升團隊協作效率

GitHub Flow

GitHub Flow — 輕量、敏捷的開源標準

適合持續發布的網頁應用程式與大多數熱門開源專案：

  • 單一主要分支： main 是唯一的主幹，永遠保持可發布狀態。
  • 功能分支開發： 開發任何功能或修復都從 main 分支拉出命名清晰的分支。
  • Pull Request 審查： 程式碼完成後提交 PR，由核心開發者審查、討論與測試。
  • 即刻合併： 通過 CI 測試與審查後，直接 Merge 回 main 分支並自動部署。
Git Flow

Git Flow — 嚴謹、多版本的發布模型

適合有固定發布週期、需支援舊版本維護的大型軟體專案：

  • 雙主幹分支： main (生產環境) 與 develop (測試整合環境)。
  • Feature 分支： 專注於開發特定新功能，完成後合併回 develop。
  • Release 分支： 準備發布新版本時從 develop 拉出，專職 Bug 修復與測試。
  • Hotfix 分支： 生產環境發現緊急漏洞，直接從 main 拉出修復，後合併回 main 與 develop。
